## 2026-10-01, fidelity guard: absolute cap on missing words (v2 part 3, task A1 review fix 2)

The review ran a 1,000-word dictation with one 25-word block removed: recall 0.975, so Light accepted it, and a 15% loss passed Standard. Flat percentages let a long cleanup silently lose a sentence or two. Fix: Light now also fails when more than 12 raw words (after pure noises) are missing, whatever the percentage (`LIGHT_MAX_MISSING` in `vox_core.py`, `Fidelity.LIGHT_MAX_MISSING`); under about 400 words the 97% rule is already stricter, so short text is unchanged. Standard keeps the percentage only, on purpose: it exists to drop false starts and self-corrections, and an absolute cap there would reject legitimate cleanups, so a long dictation can still lose a few percent in Standard (accepted trade-off; to record in the p9a spec page in task A6). A paragraph dropped by chunked cleanup is not covered by this task because chunking does not exist yet (Branch E, task E2). Tests: 3 Python tests, 8 Java checks, 7 `fidelity` rows and 1 `recall` row in `spec/golden.txt` on a 450-word text (12 missing passes, 13 fails). **Verified:** pytest 1059 passed, 2 skipped; `javatest` 18 programs passed (`FidelityTest` 101, `ParityTest` 316); compile-check OK.

## 2026-10-01, fidelity guard: big numbers, decimals, times and emails (v2 part 3, task A1 review fix)

## 2026-09-30, relay proxy mode built and documented (v2 part 2, group C)
Tasks 15 to 17 and F3, on top of the notes group (`be39d5c`, docs verified against `71f0825`). **Built:** the relay keeps an address and a write-only key per role (`stt`, `llm`) in `relay.json`, set on a new management tab or with `PUT /admin/upstream`; four whitelisted routes `/proxy/stt/...` and `/proxy/llm/...` forward to them with fixed upstream suffixes, never forward the client's `Authorization`, and have size caps, a whole-exchange deadline, four slots and fixed error shapes (411, 413, 429, 502, 503); both apps got the switch "Use my relay as the AI server" (`relay_proxy`), which only changes what `role_settings` / `Providers.roleSettings` return, so every call path follows; follow-ups made the 401, 403 and 404 hints, the meeting-notes path and the Settings status line relay-aware, and the tests derive their routes from `relay.PROXY_ROUTES`. Spec [p7f](specs/p7f-relay-proxy.md), decision [0027](decisions/0027-relay-proxy-per-role-whitelisted-write-only-keys.md).
**Rulings.** A stored key is kept only while its address is unchanged (the implementer's deviation from the brief, kept: otherwise a token holder could send the key to a host of their choosing). Routing compares the raw path with the table, no decoding. The relay's 411, 413, 429 and 503 stay `{"error": "text"}` and only 502 is OpenAI-shaped; both clients accept both shapes. The proxy does not stream. Accepted for the single-user token model: a token holder can re-point a role and read what the relay fetches (see [09-security-privacy.md](09-security-privacy.md)).
**Found by the tests.** A race between reading a role's address and its key could send the new key to the old address (fixed: one lookup). The total deadline was not enforced inside http.client's own loops (endless `100 Continue`, trailers, a trickled status line): fixed with a watchdog timer that shuts the socket down and a shared-deadline connect; on Windows a read that is already waiting is not woken by that shutdown, so a call can run to almost twice its limit (Linux cuts at the deadline). Deferred review findings are in [12-known-issues-and-roadmap.md](12-known-issues-and-roadmap.md).
**Verified:** 718 pytest tests collected, 716 passed and 2 skipped on Windows (the POSIX-only and node-only ones); 14 Java programs passed (`RelayIntegrationTest` is skipped without `--integration`), 189 golden cases on each side; the docs checker passed. The page was driven in a browser for the relay's tab; the Android page was only script-checked. **Not verified:** a real speech or chat server, `https` upstreams with real certificates, Python 3.9 at runtime, Linux, the systemd unit with `AF_INET6` on a Pi, a phone through `tailscale serve`, either app dictating through a relay on a real device, a packaged Windows build.
