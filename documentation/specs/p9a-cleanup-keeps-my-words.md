## Goal
1. A cleanup that shortened, summarised or rewrote what was said is never typed as if it were the user's words (R1).
2. The cleanup prompt reads as a formatter's brief, puts About you first, and states structure rules (paragraphs and lists only where the speaker enumerates) (R1, R2, R3).
3. Two strengths: **Light** (keep every word) is the default, **Standard** also removes fillers and false starts. The raw transcript stays available (R1).
4. The dictionary's terms are really applied, even when the model or speech-to-text spells them slightly wrong (R3).
5. A repeatable, local benchmark says which cleanup model keeps the words and how fast it is (R6, and the "fastest cleanup model" ask).

## Design

### A1. The fidelity guard (Built)
Pure rules in `windows/vox_core.py` (Java twin: `android/src/com/minhaj/vox/Fidelity.java`), called from `looks_valid(raw, cleaned, strength="light")` / `ApiClient.looksValid(raw, cleaned, strength)`.

- **Tokens.** `word_tokens(text)`: lowercase; letters, digits and combining marks are word characters (Hinglish and Devanagari work); everything else separates words, so punctuation, newlines and bullet markers do not matter; an apostrophe inside a word stays (a curly one counts as straight).
- **Allowances applied to the raw words before comparing**: spoken commands (`new line`, `new paragraph`, `question mark`, `comma`, `period`, `colon`) are not expected; `dollars`, `euros`, `pounds`, `rupees`, `percent`, `degrees` (and the singular) count as kept when cleaned has the symbol; a spoken `at` is kept when cleaned has an `@` and a spoken `dot` when cleaned has a dot between two word characters (one allowance per symbol, so an ordinary `at` still counts); spoken numbers equal digits (`twenty five` = `25`, `one hundred and five` = `105`, `a thousand` = `1000`, `two thousand twenty six` = `2026`, `three point five` = `3.5`, `p m` = `pm`), scale words too (`five million dollars` = `$5,000,000`, `two crore fifty lakh` = `2,50,00,000`, `five lakh rupees` = `Rs 5,00,000`: `rupees` is kept by `₹` or `Rs`; `thousand`, `lakh`, `million`, `crore`, `billion`, smaller after larger), ordinals first to thirty-first (`twenty first of march` = `21st of March`; `second` is read as an ordinal everywhere, on both sides, so it still matches) and `half past three` = `3:30`, and runs of digit groups join (`five five five one two` = `555-12`). Known gap (rarer forms, not handled; a failure only falls back to the raw words): fractions (`a quarter`, `three quarters`, `quarter past three`), `out of` (`three out of five` -> `3/5`), a digit then a scale word (`2 million`), `oh` as zero, ordinals above thirty-first.
- **Light** (every strength value except `standard`): pure noises (`um`, `uh`, `er`, `erm`, `ah`, `hmm`) may go. At least 97% of the other raw words must be in cleaned, at most 12 of them (`LIGHT_MAX_MISSING`) may be missing in total, and cleaned must have at least 90% of the raw word count minus one.
- **Standard**: fillers (`like`, `you know`, `i mean`, `sort of`, `kind of`) and immediate repeats may go too; at least 85% of the rest must be in cleaned and cleaned must be at least 60% as long. No absolute cap (known trade-off, ADR 0030).
- Under four words the length rule is skipped. An empty answer fails. The existing length ceiling (`1.6 x len(raw) + 40` characters) still applies in `looks_valid`.
- Comparison is a multiset (order ignored, repeats counted). Integer arithmetic only, so Python and Java agree. `word_recall(raw, cleaned)` gives the same measure as a number and is what the benchmark (A5) reuses.
- **On failure** `process_text` records `cleanup_error = "the cleanup answer looked wrong"`, sets `Result.fidelity_fallback` and uses the words as spoken: `fallback_text(raw)` (spoken commands, then a capital at the start and after each sentence end or line break) then the dictionary replacements ([0013](../decisions/0013-raw-fallback-when-cleanup-fails.md) for the raw fallback itself); the existing notice tells the user. A failed call keeps the plain `apply_spoken_commands` text.
- **Strength.** `clean_strength(value)` / `Fidelity.cleanStrength` read the setting: `standard` (any case, trimmed) is Standard, anything else, unset included, is Light. `process_text` and `DictationService.send` pass it to the prompt and the guard (A3 flipped the earlier Standard default).
- Tests: golden kinds `fidelity` (strength, raw, cleaned, expected; 84 rows), `tokens` (14) and `recall` (28), run by `tests/test_parity.py` and `ParityTest.java`; `tests/test_cleanup_fidelity.py` (101 tests, A1 and A3: tokens, recall, numbers, symbols, Light and Standard, property checks that adding only whitespace or bullet markers never lowers recall, a 1,500-word dictation, `looks_valid`, `process_text` fallback); `FidelityTest.java` (116 checks).

### A2. Prompt rewrite, About you first, structure rules (Built)
`system_prompt(style, terms, app_label, context="", strength="light")` in `windows/vox_core.py` and `ApiClient.systemPrompt(style, terms, appLabel, context, strength)` (the shorter Java overloads call it with the defaults), same text byte for byte. The order, the wording and the style table are described in [06-pipeline.md](../06-pipeline.md) ("Cleanup prompt"); in short:
1. Opens with the formatter role: copy the transcript word for word; change only punctuation, capitalisation, spelling, obvious grammar slips, paragraph breaks and list formatting; never summarise, shorten, merge, reorder, paraphrase or drop anything.
2. The About you block (`<about_speaker>`, still cleaned by `clean_context`, never echoed) is the first block after the role line, so the stable prefix caches; the dictionary line follows. The block is introduced as the most important context about the speaker, for names, spelling, jargon, language mix and tone.
3. Strength rule (`STRENGTH_TEXT`: Light keeps every spoken word except um, uh, er, erm, ah, hmm; Standard removes fillers, stutters and false starts and applies self-corrections), then the structure rule of the style plus "Never reorder or regroup what was said.", then three short examples (`EXAMPLES`) whose output has exactly the words of the input.
4. `STRUCTURE_BY_STYLE`: `casual` and `very_casual` flat; `neutral` paragraphs, and a list only when the speaker clearly counts items; `formal` and `email` paragraphs and bullets where the speaker enumerates; `notes` paragraphs and bullets; an unknown style is read as neutral. `email` and `notes` are not styles the settings offer yet.
5. The prompt for identical inputs is byte-identical (nothing depends on the time).
6. **Decision made while building:** lists are "- " bullets that keep every spoken word (including first, second, third). A numbered list would replace those words with digits and the Light guard counts an ordinal as lost, so the model would be asked for output the guard rejects. The third example shows the bullet form; a test runs every example through `fidelity_ok` in both strengths.
7. `cleanup` / `ApiClient.cleanup` pass the strength to the prompt: the `cleanup_strength` value (Light while unset) on both apps, the same value the guard gets, so prompt and guard cannot disagree.
Tests: `tests/test_prompt.py` (role first, About you right after it and before the dictionary, strength flips the filler rule, odd strengths read as Light, flat styles, unknown style, tag-like and 20,000-character About you, Hinglish About you, byte-identical output, the examples, `cleanup` sends the strength), the golden kinds `prompt`, `promptctx` (regenerated) and the new `promptstrength` (strength, style, terms, app, context, expected; 8 rows: Standard, odd strengths, `notes`, `email`, a closing tag in About you, 8,100 characters), run by `tests/test_parity.py` and `ParityTest.java`, plus the prompt checks in `ApiClientTest.java`.

### A3. Strength setting, "Use raw", fallback marker (Built)
- `cleanup_strength` is in `DEFAULT_CONFIG` as `light` and an Android preference (`Prefs.cleanupStrength()`, stored by `Bridge.save` only as `light` or `standard`); an unset or unknown value is Light everywhere (golden kind `cleanstrength`, 8 rows). Per device, not part of the synced profile.
- Both pages have a "Cleanup strength" select (Light, Standard) after "Skip AI cleanup" in Voice & audio. The row is written in each page, not in `ui-shared/` (the two pages word their settings rows differently, and `ui-shared/` holds only the palette, component styles and helper functions), so `tools/sync_ui.py --check` is unaffected.
- A guard rejection uses `fallback_text(raw)` / `ApiClient.fallbackText(raw)` (golden kind `fallback`, 13 rows incl. Hinglish and Devanagari): spoken commands applied, then a capital for the first letter of the text and of each sentence (after `.`, `!`, `?` and spaces or tabs, or after a line break). `Result.fidelity_fallback` is true; `Engine._process` logs a `fidelity guard` warning and writes `"fidelity_fallback": true` into the history entry; Android logs the same under the logcat tag `vox` and `Prefs.addHistory(..., fidelityFallback)` stores the flag. Only a guard rejection gets the capitals: a failed call, cleanup off and the Raw style keep the plain `apply_spoken_commands` text, as before.
- History has a "Use raw" button (Windows: in the entry's hover actions; Android: next to the entry's buttons) when the entry has `raw` and it differs from `text`. It copies the raw words (the transcript before cleanup and before dictionary replacements) with the existing copy bridge (`api().copy`, `V.copy`); it does not paste, because the Vox window has the focus. An entry flagged `fidelity_fallback` says "cleanup rejected, basic tidying only" next to its time or app (it said "your words as spoken" until the rules layer of 2026-10-05 tidied that text).
- Tests: `tests/test_cleanup_fidelity.py` (light default, unset config in `process_text` and in the prompt, fallback text, flag only for a rejection), `tests/test_engine_flash.py` (history keeps `raw`, flag only when set), `tests/test_ui_static.py` (both pages: the select with Light first and the Use raw button), parity kinds `cleanstrength` and `fallback`, `FidelityTest.java` and `ParityTest.java`.

### A4. Dictionary applied (Built)
There was no fuzzy pass: `apply_replacements` only does the explicit `wrong => right` lines, and part 1's "local fuzzy dictionary pass" (P3) was never built (spec p3 lists it as left out). A4 adds `fuzzy_dictionary(text, terms)` in `windows/vox_core.py` and its twin `Terms.fuzzy(text, terms)`, golden kind `fuzzydict` (39 rows). It runs after `apply_replacements` on every dictation in both apps (`process_text`; `DictationService.send`), so an explicit replacement line always wins. Full rules: [06-pipeline.md](../06-pipeline.md), section Dictionary.

- Only terms that are one word of five or more letters take part, as the plan said. So `Vox` is not applied to `box`, and a four-letter name needs a `wrong => right` line.
- A word (five or more letters, letters only) is replaced by the term as written when it equals the term ignoring case, or (a term of seven or more letters only, see the review change below) is one edit from exactly one term with the same first letter. Not touched: words on a stoplist of about 550 ordinary English words (`COMMON_WORDS`, the same text in `Terms.java`, a test compares them; this is what stops `stack` becoming `Slack`, `clause` becoming `Claude` and `grace` becoming `Grace`; review found that the first 320 words missed `clause`, `slick`, `strive`, `ample` and `Linux`, so the list was widened and golden rows added in both apps), words that differ only by a letter added at the end (`Pravins`), words equally close to two terms, and multi-word spellings (`u v raj`).
- **Changed after review (integration branch):** the one-edit guess now runs only for terms of seven or more letters (`FUZZY_NEAR_MIN_LEN`); a shorter term keeps only the case fix. With five-letter names it rewrote ordinary words (`Alice` turned `alike` into `Alice`, `Jones` turned `jokes` into `Jones`, `Raven` turned `raved` into `Raven`) and the cleanup could not prevent it because the pass runs after it. The golden `fuzzydict` rows changed with the code ([decision 0036](../decisions/0036-fuzzy-dictionary-guesses-only-for-long-terms.md)). The fidelity guard also ignores the suffix of an ordinal on both sides (`May 3` = `May 3rd` = `may third`), because "standard written form" for a date has no suffix and the guard rejected that correct cleanup.
- Idempotent. Cost: one regular-expression pass over the text plus a comparison with the terms that start with the same letter; a test puts a 2,000-word text and 200 terms under half a second.
- Rules I chose that the plan did not state: the same-first-letter rule (speech to text rarely gets the first letter wrong, and it removes most look-alike English words), the end-letter rule, the ambiguity rule, and that the stoplist also blocks the case-only fix (a term that is itself an ordinary word, such as `Grace`, is never forced onto the plain word `grace`).

### A5. Benchmark (Built)
`python tools/bench_cleanup.py [--provider P] [--model M | --compare A,B] [--strength light|standard] [--corpus FILE] [--out FILE] [--pause SECONDS]` (run from the repo with the Python that runs the app). It calls the app's real `vox_core.cleanup` (so the real prompt, reasoning fields, retries and `sanitize`) once per corpus row with the **row's** About you, dictionary terms and style, never the user's own, and scores the answer. It reads the server and key from the user's normal Vox settings.

- **Corpus** `tools/bench/corpus.jsonl`: 45 synthetic rows `{id, raw, style, terms, about, must_keep_terms}` (about 1,600 words in all): 6 short chats, 6 with names from a made-up About you (Priya Raghunathan, Kestrel Labs, Ledgerly, Kubernetes, Postgres, Terraform, gRPC, Anirudh Menon, Sofia Kowalczyk, Tomasz Wrona; some spelled wrong the way speech to text does it), 5 Hinglish, 5 filler-heavy, 5 with numbers, 3 with spoken commands, 4 enumerations, 6 long (the longest 443 words), 3 that look like questions or requests (the answer must still be the text, not a reply), 2 self-corrections. No real person, address or key; a test checks that.
- **Metrics** (pure, `tools/bench_metrics.py`, built on the guard's own tokens, so spoken numbers, symbols and commands are read the same way): `recall` (share of spoken words still there, `word_recall`), `added_rate` (share of the answer's words that were not spoken), `length_ratio` (answer words over spoken words), `term_hits` (share of `must_keep_terms` present with exactly that spelling and case, as whole words), `structure_only` (the same words in the same order, so only punctuation, case, whitespace, bullet markers and pure noises differ; a spelling fix is not hidden), and the guard itself, `looks_valid(raw, answer, strength)`. Latency is the wall time of the call (retries included, the pause between rows not). A row whose call failed counts as an error and stays out of every other number.
- **Output:** a table with one column per model (lines: latency median and p95, word recall, added words, length ratio, guard pass, term accuracy, format only, errors) and a JSON file with the numbers and each answer under `%APPDATA%\Vox\bench\bench-DATE.json` (or `--out`). Nothing is uploaded; the only network use is the cleanup calls themselves, to the chosen server.
- **Key safety:** the key is never printed or saved (error texts have it replaced by `***`). `--provider` is a preset id; it sends the requests to that server directly (the relay is bypassed, since it would ignore the provider), and the main key goes only to its own server: when the provider is not the one the settings point at, only a key set for that provider (the cleanup key of the settings) is used, otherwise the run stops with exit code 2 and says so. Plain http to a public host is refused as in the app. Exit codes: 0 done, 1 every request failed, 2 could not start.
- **Pace:** `--pause` (default 2 s) waits between requests because free tiers limit requests per minute; a 429 is recorded as an error (no automatic retry), so rerun or raise the pause.
- **Not shared with Java:** it is a Windows-side tool, so there are no golden rows for it; the guard rules it reuses have theirs.
- **What it showed already on the corpus** (offline, fake answers): copying the words back scores 100% recall and a 100% guard pass in both strengths; an answer that keeps only the first half scores 47.8% recall and a 0% guard pass. Note for reading real numbers: the guard compares the words before the dictionary pass, so a correct About-you name fix in a short text (`sophia` to `Sofia`, `ledger lee` to `Ledgerly`) lowers recall and can fail the Light guard; the corpus has such rows on purpose, and the table shows how often that costs.

## Not in this step
Chunked cleanup of very long dictations (branch E, task E2) and its chunk-level guard; the weekly self-improvement run (branch F);  any change to the default cleanup model (needs benchmark numbers from a real run first); a semantic check of meaning (the guard compares words, not meaning).

## NOT verified
- **The benchmark (A5) against a real server.** It was only run with fake providers: the request path (`vox_core.cleanup`), a real key, rate limits, a reasoning model, and the numbers a real model gets are all unseen. Whether the metrics separate a good cleanup from a bad one on real answers (for example whether `format only` is too strict for models that fix spelling) is not known; which terms the corpus rows must keep, and how speech to text would really misspell them, are my guesses.
- **The fuzzy dictionary (A4) on real dictations.** The rules were tested on made-up sentences and 39 golden rows only. Nobody has run it on real speech-to-text output: how often it fixes a real misspelling, and whether it ever changes a correct word that is one letter from a term and not on the stoplist (a real word or name that looks like another term and nobody thought to list), is unknown. Not seen on a phone or in the Windows window.
- **The pages (A3).** The Cleanup strength row and the Use raw button were checked only by `test_ui_static.py` (text checks), not in a browser against the mock bridge, not in the Windows window and not on a phone: whether the select fits, whether the hover-only button is easy to find on Windows, whether the Android history row stays tidy with the extra button. `Prefs.cleanupStrength`, `Bridge.state`/`save` and `DictationService` calling `fallbackText` compile (`javatest compile`) but never ran on a device; `SharedPreferences` is not unit-tested.
- **The default flip (A3).** Light is stricter than the Standard the code ran before, so cleanups with removed fillers are rejected more often until a model follows the Light prompt; nobody has measured how often with a real model.
- **The new prompt with a real model (A2).** Nobody has sent it to a cleanup model: whether it stops the summarising, whether the examples make a model copy their wording, whether the long dictation keeps its paragraph breaks and whether a model really keeps the speaker's words in Light is for the benchmark (A5, built, not yet run on a real model) and for real use to show. Only the text of the prompt and its order are tested.
- **Prompt length and cost.** The prompt without terms or About you is 2,607 characters, was 1,272 before (counted with `len`): about 330 more input tokens at four characters a token (an estimate, not a tokenizer count) on every cleanup; the extra latency and cost were not measured.
- **Real model output.** The thresholds (97%, 85%, 60%, 90%, 12 words) were tuned on written examples and a synthetic 1,000-word text, not on transcripts that real cleanup models returned. Whether Standard rejects too many legitimate cleanups, or Light too few, is for the benchmark (A5, built, not yet run on a real model) to show.
- **A phone.** `Fidelity.java` is covered by unit tests and golden rows and type-checks; `DictationService` calling it was not run on a device.
- **CI.** None of this has run in CI.
- **Speed.** Not measured; the guard is a few list passes over the words and adds no network call.
