# Changelog

All notable changes to Vox. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Dates are commit dates. Add a line under **Unreleased** in the same commit as any user-visible change (see [documentation/README.md](documentation/README.md)).

## [Unreleased]

Documentation: added the `documentation/` folder, `AGENTS.md` and this changelog; a checker (`documentation/tools/check_docs.py`) runs in CI. `.venv/` is now git-ignored. Added a documentation-sync routine for the end of every session: `documentation/tools/docs_todo.py` (checklist from `git diff`) and the project skill `.claude/skills/vox-doc-sync/`. Added `documentation/specs/` (design specs written before the code; first: providers and model list) and proposed ADR 0016. CI now also runs the tests and the Android build on pull requests. Providers: any OpenAI-compatible server works for speech and cleanup separately (own address and key per role), Settings shows a model list from the server's `/models` with free-text fallback and a Test button per role, and reasoning parameters are sent only where accepted (new `windows/providers.py`, `Providers.java`, `models` rows in `spec/golden.txt`). Speed: the server connections are opened when the hotkey goes down (Windows) or recording starts (Android) and reused for the upload; Android now checks the address of each role before recording. About you: a text box on the Dictionary page (both apps) whose text is added to every cleanup request as fenced background, capped at 8,000 characters; golden rows `context` and `promptctx` keep Python and Java the same. Live level: one shared meter curve on both platforms (golden `level` rows); the Windows pill draws a scrolling history of the real voice at 30 frames a second, and the Android bubble updates about 25 times a second. Privacy: the public privacy page and the accessibility description now describe any provider, separate speech and cleanup servers, the About you text and the connection warm-up. Lighter Windows build: the unused Pillow image codecs (AVIF, WebP) are left out, 85 MB to 77 MB. Voice notes (Windows): a New voice note button (Voice notes page) and tray item record a note that is written down, tidied up and saved to a searchable list (search, time filter, edit, delete) instead of being pasted. Relay (server only): `relay/relay.py`, an optional self-hosted server for notes and a profile with token auth, a change cursor and delete markers; it runs on Linux (including a Raspberry Pi), macOS and Windows and has a web page to manage and monitor it (status, notes, devices and activity, profile with secrets hidden, backup, compact, purge, new token); Windows can sync voice notes with it (Settings, Sync between devices; works offline, newer edit wins, deletes travel too); Android does too (see Added below). Profile sync (Windows): the About you text, dictionary, people, default style, cleanup switch and language follow you between devices through the relay, merged field by field; provider settings and API keys travel only if you switch on "Also share my provider settings and API keys". Speed (Windows): long recordings are sent to speech-to-text in pieces while you are still talking, so less is left to wait for when you stop (Settings switch; short recordings are unchanged). Fixed: in Settings, the status messages of the model, key, address and relay rows no longer squeeze the setting's name into a narrow column; they now sit under its description.

### Fixed
- **Android: five medium fixes in the dictation service and main screen (issue #42; nothing run on a phone):** cancelling a dictation now cuts the upload in progress, so the next dictation no longer waits behind it for minutes; temporary upload files with your voice (`vox-up-*`) left by a killed app are deleted at the next start and after every send; a finished dictation is copied to the clipboard (with a toast) when the accessibility service is off, instead of being dropped; rotating the phone no longer reloads the page and loses an unsaved note edit; a damaged notes database no longer blanks the whole app.
- **Meetings, calendar and the two pages: eight medium fixes (nothing run in a real window, with a real meeting or on a phone):** a meeting id is checked before it becomes a folder (a crafted id could make Delete remove your whole Vox data folder); a tenth of all meeting audio was dropped between the 100 ms blocks and is now kept; Improve's Revert no longer deletes cleanup rules you wrote after the change; a failed calendar fetch keeps the last events instead of hiding the next meeting for 5 minutes; calendar titles, names and the organizer are one clean line and an invite lists at most 30 attendees; the Windows Home refresh no longer closes an open Fix a word editor; the model lists are fetched once instead of every 4 seconds with the key (Windows) or on every refresh (Android); the Android remove (x) buttons on My words and People work.
- **Windows: nine medium fixes in the engine, config and paste (the clipboard code ran against the real clipboard on the development PC; nothing else was run with a live dictation):** a wrong-typed value in `config.json` (`null` for the hotkey, dictionary or people) falls back to the default instead of crashing; a damaged byte or cut-off last line in `history.jsonl` no longer hides the history or glues two entries together; a paste puts back the whole old clipboard (cells, rich text, images, files), not only its text; the dictation is marked so Win+V history and the cloud clipboard skip it; Ctrl+V works on keyboard layouts without a Latin v; a microphone plugged in after Vox started is found; recovering a saved listening session reads the audio before its silence timer starts and keeps the file after a lost microphone; a recording over 20 MB whose live transcription failed is sent in pieces instead of one upload the server refuses; note and meeting titles are no longer written to `vox.log`.
- **A tag release can no longer ship an Android APK signed with a throw-away key (not run on GitHub yet):** without the `ANDROID_KEYSTORE_B64` secret a tag build now fails with a clear error; pull-request and manual builds still build, say in the log that the key is a throw-away, and upload the APK as `Vox-android-debug-key`. `.gitignore` now also covers `.env` files, `relay.json`, `relay.db`, `*.jks`, `*.p12`, `*.pem`, `config.json` and `google_client.json` anywhere in the tree. Developer: every test now runs with its own empty profile folders and fails if it touches the real Vox profile (`test_apply_remote_rules` used to write into your real `notes.db`).
- **Android: "Save and test" no longer sends your key to an address the app refuses; the first profile sync no longer wipes the other device's settings; unsent recordings survive "Clear cache" (none of it run on a phone):** the key test follows the same address rule as every other call (plain http only for this phone, your local network and Tailscale) and says "This address is refused"; a device's first sync keeps its About you, dictionary, people and keys when the relay only holds the other device's blank defaults; unsent recordings are kept in the app's no-backup folder instead of the cache, and ones already in the cache are moved at the first start.
- **Windows window: three data-loss and injection bugs fixed (not seen in a real window yet):** adding or removing a Dictionary word, replacement or person no longer sends the whole list from the page, which wiped words your other devices had synced since the page was drawn (each edit now changes one item in the file); the Dictionary, Styles and Settings pages reload the settings when opened; the My notes autosave no longer writes the text of one meeting into the next one when you switch within 700 ms (it saves to the meeting it was typed in, and is sent before the switch); and a note id from a relay is escaped in the page and ignored unless it is 32 hex characters, so a hostile relay can no longer run script in the window.
- **Windows: meeting notes are no longer lost when the copy to Documents fails or Vox is stopped mid-meeting:** a failed export (Controlled Folder Access, a tab or newline in the calendar title) used to leave the meeting out of the list and the raw call audio on disk; the meeting is now listed first and the audio removed whatever the export does. A meeting cut off by a quit, crash or shutdown is recovered at the next start as "Unfinished meeting" with its live transcript, and its audio is removed unless "keep audio" is on. Transcript writes are atomic now. Not run with a real meeting.
- **Windows: declined and never-answered calendar invites no longer remind or start recording (not run against a real calendar):** with "start meeting notes automatically" on, a meeting you declined, or a stranger's invite you never answered, used to start the microphone and system-audio capture. Declined meetings are now ignored, an unanswered or tentative one only shows the reminder, and only a meeting you accepted starts by itself (Google responseStatus, or the iCal PARTSTAT matched by "my email").
- **Windows: the Google Calendar tokens are now protected by your Windows login** (like the API key) instead of plain JSON in `google_token.json`; an older plain file is protected on the next read, and a file that cannot be opened (another Windows user or PC) says "Connect again in Vox > Notes" instead of failing with a raw error. Not run against Google.
- **Windows: the secret iCal calendar address no longer leaks (not run against a real calendar):** it was written in plain text to `vox.log` and `calendar.json` (inside error messages and as the cache key) and to `config.json`, and the cache stayed after you cleared the link. It is now stored protected like the API key, the cache key is a short hash, a failed fetch records only "Calendar server answered 404" or "Could not reach <host>", and clearing the link deletes `calendar.json`.
- **Windows: a dictation is no longer thrown away by an unexpected error, a damaged `config.json` no longer stops Vox from starting, and a failing hotkey handler no longer kills the shortcut:** an answer the speech or cleanup server got wrong (empty `choices`, `"text": null`) now ends as a normal "kept for Retry" error or a paste of the spoken words; a paste that raises (clipboard busy) or a note that cannot be saved keeps the recording for "Retry last dictation" (and the history line is still written); `config.json` with a BOM, cut off, or not an object is moved aside as `config.json.bad-<time>` and Vox starts with the defaults; an exception in the key handler is logged and the shortcut keeps working. Not run on a desktop.
- **Android: dictation into WhatsApp and Telegram no longer starts with the word "Message"** (not run on a phone yet): those apps show the grey placeholder as the field's text, so it was kept in front of what you said. Typing now starts from an empty field when the whole text of the field is a known placeholder ("Message", "Type a message", "Text message", "Message #channel" and similar, new `HintGuard.java`); real text is never dropped. If it still happens, Settings, Bubble diagnostics shows an "insert_probe" line (app, field class, text length only, never the text) to report.
- **The dictionary no longer rewrites ordinary words into short names (both apps):** with `Alice` in the dictionary, "they look alike to me" became "they look Alice to me" (the same with `Jones` and `jokes`, `Raven` and `raved`). The one-letter guess now runs only for terms of seven or more letters; a shorter name keeps the case fix, and a name that is always misheard needs a `wrong => right` line. See [decision 0036](documentation/decisions/0036-fuzzy-dictionary-guesses-only-for-long-terms.md).
- **Dates written the usual way pass the word-keeping check (both apps):** "march fifth" cleaned to "March 5" (or "may third" to "May 3") was counted as a lost word and the cleanup was thrown away; the suffix of an ordinal (`5th`) is now ignored on both sides.
- **A closing "Thank you." is no longer dropped from a long dictation (both apps):** in a recording sent in pieces, a last piece that was only "Thank you." or "Bye" was filtered as a silence hallucination even after real speech. It is filtered now only while no text has been heard yet. Not run on a phone.
- **Android: a server that cannot read m4a no longer blocks dictations of 4 s or more (not run on a phone yet):** when a server answers 400, 415 or 422 to the m4a upload, Vox sends the same audio as WAV and remembers that server until the app restarts.
- **Windows: a device name with other characters than latin-1 (a typographic apostrophe, Hindi, an emoji) no longer breaks Test connection, the Devices card and the sync:** the name goes to the relay in the Android spelling (`?` for those characters).
- **Android bubble diagnostics no longer record which app you dictate into (not run on a phone yet):** the `insert_probe` lines had the app's package and the field's class; they now hold only buckets (length, caret place), and at most 5 of them are kept so they cannot push the bubble events out.
- **Cleanup benchmark (developer tool): your own learned cleanup rules are no longer sent to the provider** with the benchmark's 45 rows, and no longer change the answers.
- **Nested prompt tags in About you and the learned rules (both apps):** `<my_cleanup<my_cleanup_rules>_rules>` came out as a live tag after the one-pass removal; the removal now repeats until none is left.
- **Relay and CI hardening, and the MIT licence (the workflow and the POSIX file checks were not run on GitHub or a Linux machine):** a relay delete now beats a note stamped ahead of the relay's clock, note times a day or more ahead are refused, a negative or malformed `Content-Length` is a 400 instead of an unlimited read, abandoned proxy calls can no longer pile up more than 8 request bodies on Windows, and the relay refuses a data folder or `relay.json` that another user owns or can write (POSIX); plain http (with your key) is no longer accepted for 6to4, Teredo or reserved IPv4 addresses on Windows and in the relay, matching Android; the release job waits for every test job, the Windows job runs the whole test suite, an Android tag build takes its version from the tag; the repository now has an MIT `LICENSE`.

### Added
- **Android: a Microphone setting (Settings, Voice & audio; not run on a phone):** choose "Phone default" or one of the input devices Android reports (built-in, wired headset, USB, Bluetooth headset, hearing aid), worded like the Windows setting. The choice is remembered per phone by device type and name, is used for dictations and voice notes while that device is connected, and falls back to the phone's microphone with a one-time notice when it is not. No new permissions; a Bluetooth headset may still record from the phone (see [the spec](documentation/specs/p9h-android-mic-choice.md)).
- **For people new to the project:** the README is rewritten (what Vox is, features, screenshots still to take, an honest status and known-limits section, install steps with the Windows and Android warnings explained, a privacy summary, build and test, a repository map and the licence status: no licence has been chosen yet). New `CONTRIBUTING.md`, `SECURITY.md` (report vulnerabilities privately through GitHub) and `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), issue forms for bugs, feature ideas and device test reports, and a pull request template.
- **Keep listening (Windows; not run with a real microphone, server or desktop yet):** double-tap Ctrl + Win (or use the tray) and keep talking for as long as you like, up to 60 minutes. The audio is cut at pauses and turned into text while you speak. **Note** (the default) cleans everything once when you stop and saves one note; **Type** types each piece into the app you started in and pauses ("Paused: wrong window") in any other window, saving what you said meanwhile as a note. End it with a double-tap, saying "stop listening", Esc, the tray or the note shortcut. The pill shows `Listening m:ss` with a stop square. The audio is also written to `%APPDATA%\Vox\listen` while it runs, removed when it ends cleanly and kept after a failure or a crash: tray, **Recover listening session** (offered at startup) makes a note of it. Settings key `listen_target`, tray items "Keep listening: Note / Type". Android has no keep-listening (out of scope for this round). See [specs/p9e-keep-listening.md](documentation/specs/p9e-keep-listening.md), [decision 0032](documentation/decisions/0032-keep-listening-pieces-two-targets-crash-safe-buffer.md).
- **Note shortcut (Windows):** `note_hotkey`, default Ctrl+Alt+N (empty turns it off): press once to start a keep-listening note, again to stop and save, whatever the keep-listening target is. A Settings row under Voice & audio checks the combination (it needs Ctrl, Alt or Win plus one letter, digit or F key, and may not contain your dictation shortcut). The keys are not blocked.
- **Improve my cleanup (Windows, Settings; not run against a real model yet):** a stronger model (`openai/gpt-oss-120b` by default) reads a number of your saved dictations and proposes dictionary words, replacements and a few cleanup rules; you tick what to keep and every change can be reverted. **Your dictations (up to about 40,000 characters, with your About you text, dictionary and rules) are sent to your cleanup server or relay only when you press Run once and then Send** after the card has told you how many; the optional weekly tray reminder never runs it. About you suggestions are shown but never applied. See [specs/p9f-improve-my-cleanup.md](documentation/specs/p9f-improve-my-cleanup.md), [decision 0033](documentation/decisions/0033-the-improvement-run-sends-transcripts-only-on-an-explicit-button.md).
- **Learned cleanup rules (both apps):** the rules you accept are used in the cleanup prompt (setting `my_cleanup_rules`, at most 2,000 characters, in their own tagged block) and travel to your phone with the relay sync, so a phone dictation follows rules approved on the PC. The phone has no screen for them. Golden rows `rules` and `promptrules` keep Python and Java the same.
- **Android note bubble while you record** (not run on a phone yet): when a voice note is being recorded, from the Quick Settings tile, the notification, the note bubble or the app, a red bubble with the recording time now appears by itself, even when the voice note bubble switch is off. Tap it to stop and save the note; it flashes the green check (or a red ! if the note failed) and goes away unless the switch is on. Needs the accessibility service. Spec [p9g](documentation/specs/p9g-note-bubble.md) has the device checklist.
- **Android install help** (not run on a phone yet): Settings, System has an Install help card with the exact steps for "Allow restricted settings" (and a button that opens Vox's App info screen), the Play Protect "Install anyway" step and the adb way (`adb install -r`, plus an optional `appops` command), each command with a Copy button; the Home setup step links to it. It says plainly that a sideloaded APK cannot fully avoid the warnings and that Google Play (closed testing) or F-Droid are the real fixes.
- **Speed card** (both apps, Home): where the time of a dictation goes. Each dictation now keeps how long it waited for the microphone, for speech to text, for cleanup and for the text to go in; the card shows the median and the slowest 1 in 10 of each over your last 50 dictations, marks the biggest part, and lists the numbers per voice and cleanup model and for the last 10 dictations. The numbers are kept only on the device (no network, not synced). A Retry, a voice note and a dictation with history off are not timed. Not run on a phone or in the built exe yet.
- **How to set up the relay** and a fuller **Test connection** (both apps, Settings, under the relay settings): a collapsible card with the Raspberry Pi and Tailscale steps, each group of commands with a Copy button (the text is one file, `ui-shared/relay-steps.txt`, written into both pages and checked against `relay/README.md`); the Test button now also says whether the relay is reachable, whether the token works, which version it is and the name this device shows under in the relay's list (the Windows button is now labelled "Test connection" like the phone's). The decision is one pure rule in both apps (`relaycheck` rows in `spec/golden.txt`). The tray notice that appears when Vox first starts its own relay points at the card. Not run on a phone or against a real Pi yet.
- **Devices on my relay** (both apps, Settings, under the relay settings; needs a relay with `GET /devices`): a card listing the phones and PCs that have used your relay, newest first, with a "this device" badge, a dot for active (under 10 minutes), recent (under a day) or old, and "5 min ago"-style times. It refreshes with a button and after a good Test, and by itself only while sync or "Use my relay as the AI server" is on. An unreachable relay shows "Cannot reach the relay (is Tailscale running?)". The rows are one pure rule in both apps (`devices` rows in `spec/golden.txt`). Not run on a phone or against a real Pi yet.
- **Android bubble stays up** (not run on a phone yet): the accessibility service now puts the bubble back after a window change, screen on, unlock, rotation or when it connects, and a watchdog checks every 30 seconds and adds back a bubble whose window Android dropped (the diagnostics card logs it as "Bubble put back by the watchdog"). The bubble is taken off while the screen is off and comes back when it turns on. A saved position that lies outside the screen (after a rotation) is pulled back on screen. New Settings switch "Always show the bubble" keeps it up without a selected text box. The Bubble diagnostics card now shows an "Open battery settings" button while battery optimisation may stop Vox. The rules are shared pure code (`BubbleLogic`, golden rows `bubbleclamp`, `bubbleshow`, `bubbleaction`).
- **Android bubble diagnostics** (not run on a phone yet): Settings, System has a Bubble diagnostics card that says whether the accessibility service is connected (or switched on but stopped by Android), whether battery optimisation may stop Vox, and lists the last events that can make the bubble disappear (service unbound, bubble removed and why, the only-typing rule, screen on or off, unlock, rotation, an app installed or removed), with a Copy report button. The events are kept in a small file on the phone (the last 50) and are never sent anywhere. This is the first step of the "bubble keeps disappearing" fix; the watchdog and the "Always show the bubble" switch are the entry above.
- **Cleanup benchmark (a developer tool, not in the app):** `python tools/bench_cleanup.py --provider groq --model openai/gpt-oss-20b --strength light` (or `--compare a,b`) runs the real cleanup over 45 made-up transcripts and prints speed (median, p95), how many of your words are kept, added words, length, how often the fidelity guard accepts the answer, About-you spelling and whether only formatting changed. You run it with your own key (never printed); results stay in `%APPDATA%\Vox\bench\`. Not run in CI; not tried on a real model yet.
- **The dictionary is applied to what is typed (both apps):** a name or term from People or the dictionary (one word, five letters or more) is spelled as you wrote it when the dictation has it in another case (`kubernetes`), and a term of seven letters or more also when it is one letter off (`Kubernetis`), whatever the speech or cleanup model wrote. Ordinary English words are never changed, and neither are multi-word spellings; a `wrong => right` line still wins. Not tried on real speech yet.
- **Android voice notes** (not run on a phone yet): record a note without a text box and it is cleaned up and saved to a searchable list on the phone, not typed. Start it from a second, blue note bubble (Settings key `note_bubble`, drawn by the accessibility service, shows without a focused text field), from an ongoing "Record note" notification (`note_notification`) or from a Quick Settings tile "Voice note"; stop from the same place or the "Stop" action of the Vox notification. A "Note saved: title" notification follows. The Notes page lists, searches, edits and deletes notes. The two switches have no Settings row yet.
- **Android relay sync** (not run on a phone yet): Settings, Sync between devices sends the phone's voice notes and the shared profile settings (About you, dictionary, people, and by choice provider settings and API keys) to your relay and takes the PC's, with the same rules as Windows. It runs when the app opens, when the dictation service starts, when settings are saved, when a note is saved and every 90 seconds while the app's process lives; there is no background scheduler. Test connection and Sync now are in Settings.
- **Skip AI cleanup for short phrases** (both apps, Settings): phrases shorter than N words are typed as spoken, which saves a round trip to the cleanup model. The default is 3 words (what earlier versions always did); the box accepts 1 to 20, and 1 cleans up everything. Python and Java use the same rule (`gate` rows in `spec/golden.txt`). The setting does not sync between devices.
- **Run the relay from the Windows app:** the tray item "Run relay on this PC" (and `Vox.exe --relay`) starts the relay as a hidden child process of Vox, stops it when you untick the item or quit, and cannot outlive Vox. The first start shows the `tailscale serve --bg 8765` command that makes it reachable from your phone. New settings `relay_run` and `relay_port` (default 8765). Tested from source only: the built exe was not run.
- **The relay as the AI server (both apps):** a new Settings switch, "Use my relay as the AI server", sends dictation, model lists, warm-up and the Test buttons to the relay (`/proxy/stt` and `/proxy/llm`) with the relay token, so the AI provider key can live on the relay only. The relay's management page has a new tab, "AI server (proxy)", with an address and a write-only key for speech and for cleanup. Audio and text pass through the relay while this is on, and the relay keeps the keys in plain text in `relay.json` (see `documentation/09-security-privacy.md`). Tested against stand-in servers only: not yet tried with a real speech or chat server, a phone, a Raspberry Pi or Tailscale.
- **Hints through the relay:** a 401 or 403 while the relay is the AI server says to check the relay token and the AI server key set on the relay page (the relay passes an AI server's 401 and 403 on unchanged); a 404 names the relay address or the relay's AI server settings.
- **The pill and the bubble show how a dictation ended:** a green check for 0.7 s when the text landed (or a voice note was saved) and a red ! for 1.8 s when it did not (copied only, missing key, nothing heard, any send error). The tray and toast messages are unchanged. Not seen on a real screen or phone yet.
- **Home status card** (both apps): provider (or your relay), speech and cleanup model, the last connection Test, sync state, voice note count and the last dictation ("Not sent" on Android after a failed one). It replaces the word counts and "time saved".
- **Windows Styles:** pick the app for a style from a list of recent apps, or "Other..." to type an exe name.
- **Android:** switches for the note bubble and the note notification in Settings; a hint for the "Voice note" Quick Settings tile.

### Changed
- **Documentation and test examples use neutral values:** relay addresses read `https://your-pi.your-tailnet.ts.net`, and the docs no longer name private machines, local folders or a person's requests (credit stays here and in the README).
- **Double-tap no longer starts a hands-free dictation (Windows):** it starts keep listening (above). The tray's "New voice note" is unchanged. A single press while keep listening runs is ignored; ending takes a double-tap.
- **Privacy text:** the README, `docs/privacy.html`, the security page and the config page now say what keep listening and Improve my cleanup send and store (the audio file under `%APPDATA%\Vox\listen`, the saved dictations of a run, the learned rules in the profile sync).
- **Android permissions:** `VIBRATE` is no longer declared (the bubble only uses view haptics, which need no permission). `targetSdkVersion` stays 34 on purpose (see [specs/p9g2-install-safety.md](documentation/specs/p9g2-install-safety.md)).
- **Privacy page and security page** now say that each history entry keeps the timing of its dictation (Speed card; on the device only, never sent or synced) and that Android also sends long recordings in pieces and as m4a, and warms the connections when the bubble is touched (decision 0031).
- **Android is faster, on paper (not run on a phone yet; the Speed card will show the real gain):** touching the bubble opens the connections to the speech and cleanup servers before the tap lands; a long recording is cut at pauses and each piece is sent while you are still talking, so after you stop only the last piece is left; a clip of 4 seconds or more goes up as AAC (m4a), a quarter of the size of the WAV (the WAV is used if the encoder fails); the cleanup request has temperature 0 and a token limit sized to the text (at least 256, with extra room for thinking models such as gpt-oss, Qwen3 and DeepSeek R1; an answer cut off at the limit counts as a failed cleanup and the words are typed as spoken); connecting gives up after 5 s with one immediate retry, and the other waits scale with the length of the audio and the text instead of a flat 60 s; the microphone is set up off the main thread, and the text reaches the screen before the notification is updated. A failed piece, a failed encoder or a text that comes back empty falls back to sending the whole recording as before.
- **Test connection (Windows):** the button is now called "Test connection" like the phone's, and a good test also saves the address and token you typed (the phone already did). The relay has a new route, `GET /devices`, which the Devices card uses; update `relay.py` on your Pi to get the card's list (an older relay answers "too old to list devices").
- **A cleanup that drops your words is rejected (both apps):** the AI cleanup answer must keep the words you said (in Light strength 97% of them, in Standard 85% after fillers and repeats are ignored; in Light at most 12 missing words in total; spoken numbers (`two hundred dollars`, `two thousand twenty six`, `one hundred and five`, `three point five`, `three thirty p m`, `five million dollars` for `$5,000,000`, `two crore fifty lakh`), ordinals up to thirty-first (`twenty first of march` for `21st of March`), `half past three` for `3:30`, spoken email parts (`john at gmail dot com`), currency words (`rupees` for `₹` or `Rs`) and spoken commands are allowed for; not understood yet, so they fall back to your words: fractions, `out of`, `quarter past`, `2 million`); a summary or a rewrite that loses words now falls back to your words as spoken, as a failed cleanup does. The rejected answer is replaced by your words as spoken with a capital letter at the start and after each sentence end or line break, and the history entry is marked.
- **Cleanup strength, Light by default, and "Use raw" (both apps):** Settings, Voice & audio has a new "Cleanup strength" choice. **Light** (now the default, also when nothing was ever chosen) keeps every word you said and only fixes punctuation, capitals, spelling and paragraphs; **Standard** (what the app did before) also removes fillers and false starts. This changes behaviour: with Light, an AI answer that removed your "you know" or "like" is now rejected and your words are typed as spoken, so pick Standard if you want fillers removed. History has a new "Use raw" button on every entry whose words as spoken differ from the typed text: it copies the words as spoken. Not tried on a screen or a phone yet.
- **A cleanup prompt that keeps your words (both apps):** the prompt now tells the model to copy the transcript word for word and change only punctuation, capitals, spelling, obvious grammar slips, paragraph breaks and lists, and never to summarise, shorten, merge, reorder or drop anything. The "About you" text now comes first, as the most important context (names, spelling, jargon, language mix, tone); a Light or Standard rule says whether fillers stay; paragraph and list rules depend on the style (chat styles stay flat, lists are "- " bullets only when you enumerate) and three short examples show the result. Not tried against a real model yet.
- **Android start is faster:** the dictation service starts recording as soon as it is in the foreground; the fixed 400 ms and 350 ms waits are gone.
